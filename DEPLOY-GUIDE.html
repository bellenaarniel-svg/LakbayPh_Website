Before you start

You'll need three things — all free:

  • ✅ The project ZIP I gave you: lakbayph-van-rental.zip — unzip it on your computer first.
  • ✅ A GitHub account (free) — stores your code.
  • ✅ A Render account (free) — runs your code as a live website.
⚠️ Why your earlier tries failed Render needs package.json at the very TOP of the repo. Your uploads kept putting files inside a folder, so Render couldn't find it. Step 2 & 3 below fix exactly that.
1

Create a GitHub repository

Go to github.com/new (sign up first if you don't have an account). Fill it in like this:

Name it lakbayph-van-rental, keep it Public, leave "Add a README" UNCHECKED, then click Create repository.

2

Upload your files the RIGHT way

On the new empty repo page, click “uploading an existing file”.

Now the most important part. Open the folder you unzipped. Select the files INSIDE it — not the folder itself — and drag them onto the page:

Drag the contents (left), never the containing folder (right). This is what caused your repeated error.

Scroll down, type a message like Initial commit, and click Commit changes:

3

Verify the structure ✅ (30-second check)

After committing, look at your repo's main page. You must see package.json and server.js listed directly — not inside a folder:

✓ If you see this, you're golden. If instead you see one folder (like lakbayph-van-rental/) containing everything, delete the repo and redo Step 2 — this time dragging the files inside the folder.
4

Create a Render account

Go to render.com → Get Started → “Sign in with GitHub”. This lets Render see your repositories.

Approve the GitHub authorization when it asks. You'll land on the Render dashboard.

5

Create a Web Service from your repo

On the Render dashboard, click New + (top right) → Web Service.

Find lakbayph-van-rental in the list and click Connect.

💡 Bonus: it may auto-configure Because I included a render.yaml, Render might detect a "Blueprint" and fill in the settings automatically. If it offers that, accept it — then just add the two environment variables in Step 6.
6

Settings & admin password

Fill the form exactly like this (most will already be correct):

Scroll to Environment Variables → Add Environment Variable, and add these two so your admin login is secure:

7

Deploy & get your live link

Click the big Deploy Web Service button at the bottom. Render will show a live log. Wait for the green success lines (~2–4 minutes):

At the top of the page you'll see your live URL:

🎉 That's your live site! Share that link with customers. The booking form, admin dashboard, calendar, and Messenger chat all work here (unlike GitHub Pages).
8

Test it + how to update later

Test: open your .onrender.com link →

  • Make a test booking on the main page.
  • Click Admin Login → use the ADMIN_USER / ADMIN_PASS you set → check the booking appears in the dashboard.
  • Click the 💬 chat bubble → Continue on Messenger → confirms it opens your Facebook page.

To update the site later: just edit the files on GitHub (or re-upload). Every time GitHub changes, Render auto-redeploys within a couple minutes. No extra steps.

💤 Free plan note Render's free service "sleeps" after ~15 minutes of no visitors, so the first visit after idle takes ~30–50 seconds to wake up. Upgrading to a paid instance (or pinging it) keeps it always-on. Your database is on a persistent disk (set by render.yaml), so bookings are saved.
